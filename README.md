# Data Analysis Using Python, Pandas 



A small script that fetches a list of customers from the JSONPlaceholder API,
works through the data with plain Python structures (dicts, lists, sets), and
then exports the results as CSV files and bar charts.

## What it does

`starter.py`:

1. **Fetch** — pulls the customer list from `https://jsonplaceholder.typicode.com/users`
   with `requests` (10s timeout, errors reported instead of crashing).
2. **Explore** — walks the nested JSON and prints every key with its type.
3. **Extract** — flattens each customer into one dict: id, name, username, email,
   email domain, phone, city, zipcode, lat/lng, company, website.
4. **Summarise** — computes distinct cities, customers per city and customers per
   email domain using plain loops/dict comprehensions (no `Counter`, no pandas).
5. **Export** — writes a pandas DataFrame to CSV and renders horizontal bar charts
   with matplotlib (`Agg` backend, so no display is required).

## What your README should answer

### 2. Nested attributes and the deepest one

`explore()` walks each customer record recursively. The top-level record is a dict with 8 keys, and only two of its values are nested:

- `address` (a dict) → reaches `street`, `suite`, `city`, `zipcode`, `geo`.
- `company` (a dict) → reaches `name`, `catchPhrase`, `bs`.

`address` is the only attribute whose value is a dict. Inside `address`, `geo` is the only sub-dict, and it holds the deepest attributes: `lat` and `lng`. So the deepest reachable values are `address.geo.lat` and `address.geo.lng`, both of which you convert to `float` in `extract_attributes()`. The explore output starts like this:

address: dict
   street: str
   suite: str
   city: str
   zipcode: str
   geo: dict
      lat: str
      lng: str

### 8. Which chart is more useful

`customer_distribution.png` (one bar per city) is the weaker chart here: there are 10 unique cities and 10 customers, so every city appears exactly once — all bars are the same height and the chart tells you nothing.

`email_tld_distribution.png` is the more useful chart: the email top-level domain (`biz`, `tv`, `net`, `org`, `ca`, `info`, `me`, `io`) shows the customer's email provider, so you can see that `biz` dominates (3 of 10 customers) while every other TLD appears once. That is far more actionable for marketing than a city chart where nothing clusters.

## Setup

Requires Python 3.14+.

Using [uv](https://docs.astral.sh/uv/) (the lockfile is already here):

```bash
uv sync
```

Or with pip:

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Run

```bash
python starter.py
```

The script prints the raw customer data, the nested key structure, the flat
records, the city/domain counts and the DataFrame shape/dtypes, then writes the
CSVs and charts listed above into `output/`.

`starter.py` is the completed solution — every function is implemented. Run it with `python starter.py` to reproduce the full exercise.

## Dependencies

- `requests` — HTTP fetch from the API
- `pandas` — DataFrame handling and CSV export
- `matplotlib` — bar charts saved to `output/`
